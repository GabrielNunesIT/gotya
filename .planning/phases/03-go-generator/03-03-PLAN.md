<!-- Schema types for RPC/Action/Notification — from schema/schema.go -->
```go
type RPC struct{ *BaseNode }           // Children contains *schema.Input and *schema.Output
type Action struct{ *BaseNode }        // same children shape as RPC
type Notification struct{ *BaseNode }  // Children are data nodes directly (no Input/Output)
type Input struct{ *BaseNode }         // child key: "input" in parent's Children map
type Output struct{ *BaseNode }        // child key: "output" in parent's Children map
```

<!-- Node location confirmed by RESEARCH.md open question resolution -->
<!-- Top-level RPCs: added via mod.AddNode() — appear in mod.Nodes -->
<!-- Actions: attached via parent.AddChild() — appear in container/list Children map -->
<!-- This means generateNode must handle Action when walking container/list children -->

  <action>
    Step 1 — Extend hasValidNodes:
    Add to the switch in hasValidNodes:
      case *schema.RPC, *schema.Action, *schema.Notification:
          return true

    Step 2 — Add generateNode cases:
    In generateNode's switch, add:

      case *schema.RPC, *schema.Action:
          prefix := prefix + toCamelCaseTitle(n.Name())
          // Emit Input struct
          if inputNode, ok := n.GetBase().Children["input"]; ok {
              if inp, ok := inputNode.(*schema.Input); ok {
                  inputStructName := prefix + "Input"
                  if !visited[inputStructName] {
                      visited[inputStructName] = true
                      // emit: type XxxInput struct { <fields from inp.Children> }
                      if err := g.generateRPCStruct(inputStructName, inp.Children, w); err != nil {
                          return err
                      }
                  }
              }
          }
          // Emit Output struct
          if outputNode, ok := n.GetBase().Children["output"]; ok {
              if out, ok := outputNode.(*schema.Output); ok {
                  outputStructName := prefix + "Output"
                  if !visited[outputStructName] {
                      visited[outputStructName] = true
                      if err := g.generateRPCStruct(outputStructName, out.Children, w); err != nil {
                          return err
                      }
                  }
              }
          }
          return nil

      case *schema.Notification:
          notifStructName := prefix + toCamelCaseTitle(n.Name()) + "Notification"
          if !visited[notifStructName] {
              visited[notifStructName] = true
              if err := g.generateRPCStruct(notifStructName, n.GetBase().Children, w); err != nil {
                  return err
              }
          }
          return nil

    Step 3 — Add generateRPCStruct helper function (new private function):
      func (g *GoGenerator) generateRPCStruct(structName string, children map[string]schema.Node, w io.Writer) error
      Emits: "type {structName} struct {\n" then one field per child using generateField,
      then "}\n\n". For children that are Containers or Lists, emit the pointer/slice type
      using the existing toCamelCaseTitle pattern. Use namespace="" (RPCs have no namespace
      in field tags for v1 simplicity). Sort children by name for deterministic output.

    Step 4 — Post-loop pass in GenerateDevice:
    After the closing brace of `for _, treeType := range []string{"Config", "State"}`,
    add a new loop:

      for _, mod := range modules {
          prefix := toCamelCaseTitle(mod.Name)
          for _, name := range getOrderedChildNames(mod.Nodes) {
              node := mod.Nodes[name]
              switch node.(type) {
              case *schema.RPC, *schema.Action, *schema.Notification:
                  if err := g.generateNode(node, &buf, visited, prefix, "", mod.Namespace, false); err != nil {
                      return err
                  }
              }
          }
      }

    This emits RPC/Action/Notification ONCE, outside the Config/State duplication loop.

    Note on Actions: Per RFC 7950 §7.15, actions are attached to data nodes (containers/lists),
    not directly to the module. They appear in container.Children, not mod.Nodes. The generateNode
    Container case calls generateStruct which calls generateField for children — but generateField
    does not recurse into Action nodes. For v1, add Action handling to generateStruct's child
    iteration so action structs are emitted when a container is processed. Verify this in the test.
